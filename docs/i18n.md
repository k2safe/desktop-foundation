# I18n

桌面底座提供一层轻量多语言能力，用来覆盖通用 UI、登录壳、调试面板、表格、弹窗、toast、文件选择、设置页等基础文案。业务产品仍然拥有自己的品牌、菜单、页面标题、字段名、接口错误和业务文案。

当前能力包括：

- `LocaleProvider` / `DesktopAppShell` 注入语言、字典和覆盖文案
- `useLocale().t()` 翻译通用 UI 文案
- `useLocale().format` 统一数字、金额、日期和时间格式化
- 缺失 key 诊断回调
- `getMissingLocaleKeys()` 构建期/CI 辅助检查

## 内置语言

- `zh-CN`
- `en-US`

默认语言是 `zh-CN`。如果产品不传任何语言配置，底座通用文案会使用中文默认值。

## App Shell 接入

产品项目优先从 `DesktopAppShell` 传入语言配置：

```tsx
import { DesktopAppShell } from "@desktop-foundation/app-shell";

const messages = {
  "layout.logout": "Sign out",
  "login.signIn": "Enter workspace"
};

export function App() {
  return (
    <DesktopAppShell theme={theme} client={clientConfig} locale="en-US" messages={messages}>
      <Routes />
    </DesktopAppShell>
  );
}
```

自定义语言使用 `dictionaries`：

```tsx
const dictionaries = {
  "ja-JP": {
    "common.cancel": "キャンセル",
    "common.confirm": "確認",
    "layout.logout": "ログアウト"
  }
};

<DesktopAppShell
  locale="ja-JP"
  dictionaries={dictionaries}
  formatDefaults={{ currency: "JPY", timeZone: "Asia/Tokyo" }}
  theme={theme}
  client={clientConfig}
>
  <Routes />
</DesktopAppShell>;
```

## UI 组件单独使用

如果没有使用 `DesktopAppShell`，可以在 UI 层直接包 `LocaleProvider`：

```tsx
import { LocaleProvider } from "@desktop-foundation/ui-react";

<LocaleProvider locale="en-US">
  <ProductScreen />
</LocaleProvider>;
```

组件内部可以通过 `useLocale()` 读取：

```tsx
import { useLocale } from "@desktop-foundation/ui-react";

function SaveButton() {
  const { t } = useLocale();
  return <button type="button">{t("common.confirm")}</button>;
}
```

## 数字、日期和金额格式化

底座用浏览器/运行时内置 `Intl` 做格式化。产品只在入口传默认策略，页面组件通过 `useLocale().format` 使用：

```tsx
<DesktopAppShell
  theme={theme}
  client={client}
  locale={productAdapter.locale}
  formatDefaults={{
    currency: productAdapter.defaultCurrency,
    timeZone: productAdapter.timeZone
  }}
>
  <Routes />
</DesktopAppShell>
```

页面内：

```tsx
const { format } = useLocale();

format.currency(1280.5, "USD");
format.number(1280.5, { maximumFractionDigits: 2 });
format.date("2026-06-04T10:00:00Z");
format.time(Date.now());
format.dateTime(Date.now());
```

也可以在非 React 边界直接创建 formatter：

```ts
import { createLocaleFormatters } from "@desktop-foundation/ui-react";

const format = createLocaleFormatters("en-US", { currency: "USD", timeZone: "America/New_York" });
format.currency(1280.5);
```

## 缺失 Key 诊断

当目标语言缺少 key 时，底座会落回中文默认字典或调用方传入的 fallback；产品可以通过回调记录诊断，不需要让页面崩溃：

```tsx
<DesktopAppShell
  theme={theme}
  client={client}
  locale={productAdapter.locale}
  dictionaries={productAdapter.dictionaries}
  onMissingLocaleKey={(event) => {
    reportDiagnostic("i18n.missing_key", event);
  }}
  warnOnMissingLocaleKey={import.meta.env.DEV}
>
  <Routes />
</DesktopAppShell>
```

`LocaleMissingKeyEvent` 只包含 `key`、`locale`、`fallback`、`valueKeys` 和时间戳，不包含实际 values，避免把业务值写进诊断。

构建期或 CI 可以用 `getMissingLocaleKeys()` 检查自定义语言包：

```ts
import { getMissingLocaleKeys, zhCNMessages } from "@desktop-foundation/ui-react";

const missingKeys = getMissingLocaleKeys(zhCNMessages, productDictionaries["en-US"]);
if (missingKeys.length) {
  throw new Error(`Missing locale keys: ${missingKeys.join(", ")}`);
}
```

## 覆盖规则

优先级从低到高：

1. `zh-CN` 默认字典
2. 内置目标语言字典，比如 `en-US`
3. `dictionaries[locale]`
4. `messages`
5. 业务组件显式传入的 prop，比如 `submitLabel`、`title`、`emptyTitle`

这意味着产品可以只覆盖少量 key，不需要复制整份字典。业务显式传入的文案永远优先，底座不会替产品翻译业务页面。

## Product Adapter 推荐形态

```tsx
import type { LocaleCode, LocaleDictionary } from "@desktop-foundation/ui-react";

export interface ProductAdapter {
  locale: LocaleCode;
  messages?: LocaleDictionary;
  dictionaries?: Record<string, LocaleDictionary>;
  defaultCurrency?: string;
  timeZone?: string;
}

export const productAdapter: ProductAdapter = {
  locale: "en-US",
  messages: {
    "layout.logout": "Sign out"
  }
};
```

然后在入口传给 `DesktopAppShell`：

```tsx
<DesktopAppShell
  theme={productAdapter.theme}
  client={client}
  locale={productAdapter.locale}
  messages={productAdapter.messages}
  dictionaries={productAdapter.dictionaries}
  formatDefaults={{ currency: productAdapter.defaultCurrency, timeZone: productAdapter.timeZone }}
  onMissingLocaleKey={(event) => client.diagnostics.recordAuditEvent({ action: "i18n.missing_key", level: "warn", ok: false, metadata: event })}
>
  <Routes />
</DesktopAppShell>
```

## 底座边界

底座负责：

- 通用按钮、弹窗、toast、表格、筛选、命令面板、登录壳默认文案
- `zh-CN` / `en-US` 内置字典
- 自定义语言字典注入
- `{count}`、`{key}` 这类简单占位符替换
- 数字、日期、时间和金额的统一 formatter
- 缺失 key 诊断事件形状和 CI 辅助函数

产品负责：

- 产品名、菜单、路由、页面标题
- 业务字段、接口错误、权限名
- 需要专业翻译或上下文强相关的文案
- 租户/账号语言偏好的来源和持久化策略
